# pika op 1.5.0 — standalone edition

Version 1.5 reimplements compatible Axion-style ESP features in the existing external renderer: SCOPED, DEFUSING and IMMUNE flags, health-based bar colours, optional spotted-state box colours, and optional head markers. Visuals contains the toggles. Flags use schema fields from the bundled dump and share the existing remote-metadata cache, so their displayed values may lag by up to 100 ms. Missing reads produce no positive flag. Head markers prefer a supplied verified head joint and otherwise use approximate collision bounds. The new details respect adaptive distance detail and label collision filtering.

This is a partial feature migration rather than a port of Axion's internal engine integration. Boxes, health, names, weapons, numerical ammo, armor, distance, conditional skeletons, tracking presets and settings already existed. Magazine bars are omitted because a verified magazine-capacity data pointer is unavailable. Item ESP, chams, silent aim, rapid fire, anti-aim, engine FOV changes, night/sky effects, no-flash/no-smoke changes, third person, impact changes, inventory/skin modifications and planting exploits are not migrated. Those require separate engine integration or additional validated data and cannot be represented by merely copying the C++ code into this external C# app. No new engine hooks or game-memory writes are introduced by this visual update.

Tracking > Weapon profile > Aggressive selects head targeting, 40 ms exponential smoothing, a 220-pixel acquisition radius, a 0.25-pixel deadzone and a 3200-counts-per-second movement cap per axis. Selecting it enables the local spotted-state filter and disables automatic weapon profile switching. It preserves the hold key, teammate choice and scoped-only setting, and does not enable tracking. Turn on tracking separately and hold the configured key. F8 stops tracking. Saved profile edits can override the response values; Load factory values restores them. This profile does not change damage, fire automatically, compensate spread or establish exact bone positions.

Double-click pika_op_standalone.exe. No activation key, license server, BAT, or adjacent manifest files are required. Windows x64 with .NET Framework 4.8 is required. Tracking starts disabled; F8 disables it and F6 pauses the session.

The executable includes the interface, icon, supplied offsets, client schema, dump build metadata, and RSA-signed integrity data. Its startup and periodic checks verify the signed executable payload. This is application-level tamper checking, not Authenticode publisher signing, obfuscation, or an uncrackable protection system. Existing local activation files are ignored. Licensing.cs, LicenseKey.cs and owner issuance tools remain as legacy source artifacts for older releases and are excluded from the current build.

The bundled dump targets build 14192. A different game build requires matching updated dumps; validation refuses a mismatch. Diagnostics > Use bundled dump selects the embedded data. Choose dump folder allows an updated external dump. Missing saved dump directories fall back to the bundled data. Settings, logs and optional email configuration are stored under the current Windows user's LocalAppData\PikaOp folder. No email is sent unless locally configured and enabled; device details remain opt-in.

Adaptive distance detail reduces clutter: boxes below 72 screen pixels use thin lines and compact labels. Boxes below 28 pixels omit labels and bars, except selected-target labels. Overlapping labels give priority to the selected target and nearer players. Visuals contains the adaptive-detail toggle. Tracking provides saved weapon profiles, hold keys, target selection, smoothing, deadzone, and mouse-count speed limits.

Require local spotted state is a visibility proxy, not an exact wall or smoke trace. Enemy review reports experimental rapid-turn observations rather than confirmed cheating. Legitimate flicks and network updates can trigger it. Skeletons need an independently verified optional profile. Live accuracy and smoothness still depend on the game, calibration, and display conditions.

Build with build.ps1 -OutputFolder standalone-1.4.0. The compiler uses installed .NET Framework libraries and embeds the three dump resources from the owner's Downloads dump folder. The private RSA signing key remains in the owner's Windows key store. The build excludes activation code and appends the signed release metadata to the executable.

The --self-test mode checks projection, display-detail rules, label overlap, tracking settings, bundled dumps, exclusion of activation code, DPAPI, and integrity rejection. The --smoke mode checks all nine UI pages and the native overlay without tracking input. The --live-check mode reads a telemetry sample without tracking input. Diagnostic outputs are written beside the executable when these modes are explicitly used.
